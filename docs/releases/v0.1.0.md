# lake-polars v0.1.0

The first release of lake-polars, powered by Polars: the analytics service behind lake's `polars`
service kind. Upload datasets, query them with Polars SQL, behind a bearer token. MIT-licensed.

Tracking issue: https://github.com/oramasearch/lake-polars/issues/15. This release was cut from
`dev` without a release plan and has not run on a dev environment (see *Where it has run*).

## What it includes

Everything, as this is the first release. The reference is [`docs/api.md`](../api.md).

**Routes** (every one but `/healthz` needs `Authorization: Bearer <token>`):

| Route | What |
|---|---|
| `POST /v1/datasets/<name>` | upload CSV, JSON Lines or Parquet (by `Content-Type` or `?format=`), stored as `<name>.parquet`; replaces a dataset of that name atomically (`201` new, `200` replaced) |
| `GET /v1/datasets` | every dataset's name, rows, columns and types, and size, from the Parquet footers |
| `DELETE /v1/datasets/<name>` | remove a dataset |
| `POST /v1/query` | `{"sql": "..."}`: Polars SQL over every dataset as a lazy Parquet scan; at most 10,000 rows, `truncated` when cut |
| `GET /healthz` | `200` when the data directory is usable (no token) |

**Configuration:** `LAKE_POLARS_TOKEN` (required), `LAKE_POLARS_DIR`, `LAKE_POLARS_ADDR`,
`LAKE_POLARS_MAX_BODY_BYTES`, `LAKE_POLARS_QUERY_TIMEOUT_SECONDS`,
`LAKE_POLARS_UPLOAD_TIMEOUT_SECONDS`, `LAKE_POLARS_MAX_CONCURRENT`, `LAKE_POLARS_MEMORY_LIMIT`,
`LAKE_POLARS_THREADS`. `lake-polars --version` prints the version.

**The SQL sandbox:** exactly one query statement; every FROM item a dataset name, a subquery, a
join or an `UNNEST` (so `read_csv('/etc/passwd')` and the other file-reading table functions are
refused); at most 1,000 operators; `lpad` / `rpad` lengths are literals of at most 65,536.

**Limits and guards:** a query time limit, a concurrency limit shared by queries and uploads (an
upload takes its slot before its body is read), an upload cap and a Parquet decoded-size guard tied
to the memory limit, a 64 MiB stack per query, a header read timeout, at most 512 connections, and
deadlines on every body.

**Values:** every Polars type as JSON (`docs/api.md`, *Values*), with integers above 64 bits and
decimals as strings and binary as `{"$base64": ...}`.

**Errors:** one shape, `{"error": {"code", "message"}}`, with the codes `invalid_request`,
`invalid_name`, `invalid_data`, `sql_error`, `forbidden_sql`, `unauthorized`, `not_found`,
`method_not_allowed`, `timeout`, `body_too_large`, `unsupported_format`, `internal`,
`unavailable` and `disk_full`.

**Logging:** one JSON line per request (method, path, status, sizes, duration); never the SQL, a
body, data, the query string, a header or the token; a panic logs only its location.

**The image:** one statically linked musl binary on `scratch`, user `65532`, `/data` for the
datasets; built on digest-pinned `rust:1.95-alpine`. No GPL or LGPL code ships in it.

**The open-source release:** MIT `LICENSE` and `COPYRIGHT` (OramaSearch, Inc.), SPDX headers,
`THIRD_PARTY_LICENSES` (generated by `tools/third-party-licenses.py`), an SBOM in SPDX and
CycloneDX (`tools/sbom.py`), `SECURITY.md`, `CONTRIBUTING.md` with the CLA, `CODE_OF_CONDUCT.md`,
and [`docs/security.md`](../security.md) with the security model and the pre-release review.

Pull requests: #2 (security policy), #3 (public tree), #4 (licences), #6 (security fixes, the
`scratch` image, the README).

## What it does not include

- Shared storage across workers: each worker has its own datasets, so run one instance.
- Replication or backups of a worker's volume.
- Cancelling a running query, or bounding one query's memory below the container's limit.
- TLS: plain HTTP, behind the platform's mesh or ingress.
- A public image: the Docker Hub repository stays private until the open-source launch.

## Known issues

Security first.

- **Security:** none open. The pre-release review's eight findings (#7 to #14) are fixed in this
  release; see [`docs/security.md`](../security.md).
- Datasets are per worker, with no replication or backup
  (https://github.com/oramasearch/orama-operator/issues/453 for backups).
- Results stop at 10,000 rows; a connector that needs more must page
  (https://github.com/oramasearch/zetta/issues/1382).
- The operator's default image is `oramasearch/lake-polars:0.1.0`, without the `v` this release is
  tagged with: the operator's default moves to `v0.1.0` before a Polars service can start on it.

## Where it has run

Not on a cluster yet. The binary and its tests ran on macOS (arm64); the image is built for
`linux/amd64` on the cluster BuildKit from the `v0.1.0` tag, and its digest is recorded here when it
is.
